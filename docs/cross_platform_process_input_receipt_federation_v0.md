# Cross-Platform Process Input Receipt Federation v0

LOOM now joins native process-input receipt evidence from three closed CI
platforms:

- macOS arm64, using the POSIX unbuffered parent pipe writer;
- Linux x86_64, using the POSIX unbuffered parent pipe writer;
- Windows x86_64, using direct synchronous Win32 `WriteFile` calls.

The federation proves **parent-side pipe-delivery semantic concordance**. Each
native witness must prove that the exact expected stdin digest and byte count
were accepted by the parent-side pipe writer, that the writer end closed, and
that partial delivery, receipt tampering, and execution rebinding fail closed.
The receipt must remain content-addressed, execution-bound, non-authorizing,
and free of embedded payload bytes.

This claim does **not** equate POSIX writes with Win32 `WriteFile`, require the
same payload bytes on every host, or prove that the child process parsed,
retained, or semantically consumed the accepted bytes.

## Native witnesses

Linux and macOS emit
`loom-posix-process-input-receipt-ci-witness/v0` only after the real native
Bounded Execution test produces a valid `loom-action-process-input-receipt/v0`
and passes early-close and receipt-tamper adversaries. Windows contributes its
existing `loom-windows-process-input-receipt-ci-witness/v0`, generated by
`verify-windows-bounded-execution` after direct native pipe-write testing.

`loom_process_input_federation.py` validates every nested Execution and receipt
before building
`loom-cross-platform-process-input-receipt-federation/v0`. All three witnesses
must bind one exact Git commit, one GitHub Actions run and attempt, and three
distinct native jobs. Unknown fields, duplicate platforms, revision drift,
cross-run mixing, malformed hashes, failed checks, incomplete writes, or false
consumption claims are rejected.

## CI artifact

The `federate-process-input-evidence` job downloads exactly the
`process-input-platform-*` artifacts and invokes
`tools/verify_process_input_federation_ci.py` with `GITHUB_SHA`. It emits
`cross-platform-process-input-receipt-federation-v0` only after all three
native inputs pass closed validation.

The federation is test-only and non-authorizing. It grants no production
authority, proves no native operator presence, does not prove process
consumption, and does not authorize a scheduler or another host action.
